Marking Criteria11     Section 1: Overview of Assessment This assignment assesses the following module learning outcomes:  Understand and use a Unified Modelling Language (UML) modelling tool and Java- based Interactive Development Environment (IDE) to develop object-oriented software implementations appropriate to level 2 complexity Use an appropriate development environment to design and implement persistence within a distributed architecture at an introductory level. Design and implement concurrent systems and distributed systems. Design and implement Graphical User Interface (GUIs). Develop the necessary professional skills considering Agile approach while working in a group. The assignment is worth 80% of the overall mark for the module. The assessment is designed to allow you to use your learning and play to your strengths. You can always seek advice and/or interim verbal feedback from your tutors during practical sessions.    Broadly speaking, the assignment requires you to design and implement a moderately realistic Object-Oriented System. You will produce detailed Object models and designs from system requirements; using the modelling concepts provided by UML. You will then map the designs into Java code and perform thorough testing.  The assignment is described in more detail in section 2. This is a GROUP assignment.  Working on this assignment will help you to understand more clearly the concepts, problems, and techniques of Object-Oriented Systems, and how these can be used to design and implement a reasonably large size software systems while working in a team (to a professional standard).  Section 2: Task Specification   Based on the case study provided:Task I (Weighting 80%)  Exercise 1: Entity–Relationship Diagram (ERD)Design the Entity–Relationship Diagram (ERD) for the system, capturing all entities, attributes, and relationships required to support data persistence in a distributed architecture.Identify primary keys, foreign keys, and cardinalities for each relationship. Ensure your design follows good normalization practices appropriate for an introductory level.Once your ERD is complete, translate it into a logical schema (e.g., table definitions) that could be implemented in a database. You may adjust and refine your diagram and schema based on feedback from your instructor before moving to implementation in later exercises.Be clear, consistent, and professional in your diagram layout, and provide a short explanation of any design choices or assumptions you made.Exercise 2: Implementation Develop the system using Vaadin technology considering all the functionalities described above.  Initially implement the “business logic” or “model” Java classes you designed in the Class Diagram. You may expand and modify the classes based on any feedback you have received. Subsequently, develop the Graphical User Interface (GUI) to use and “call” your model classes. You may either “hand code” the GUI or use Vaadin studio to design and implement your User Interface. You should be creative and come up with your own User Interface Design. *Consider ONLY three Core functionalities Exercise 3 Testing Testing is part of the software development – you should use a test strategy to test your system thoroughly. As a minimum you should create test cases for all the Use Cases you identified in task 1. You should also create further test cases to exercise any validation you have implemented. Deliberately feed your system out of range or incorrect data to attempt to make it fail.  Produce a table of test cases as illustrated in Table 1. For the “Actual Result” column you may optionally provide or refer to a screenshot of your application in an appendix.  A single example test case has been provided for you.
