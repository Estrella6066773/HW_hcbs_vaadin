# HCBS 四人分工（按模块垂直负责）

> **原则：** 每人负责 **一个完整模块** —— 该模块的 Service、View、Model、Repository、DTO、测试、相关配置，**全部归一人**。  
> **禁止：** 按「前端 / 业务 / 测试」横向切分。  
> 点击文件名可在编辑器中打开。

---

## 分工原则

```text
成员 A ── 模块 1：影片浏览（Home）
成员 B ── 模块 2：订票（Booking）
成员 C ── 模块 3：账户 · 取消 · 导航
成员 D ── 模块 4：数据管理 · 平台基础
```

每人答辩时讲 **自己模块的端到端流程**（从页面 → Service → 数据库 → 测试用例）。

---

## 总览

| 成员 | 模块 | 侧栏 / 路由 | 代码量（约） | 单元测试数 |
|:----:|------|-------------|:------------:|:----------:|
| **A** | 影片浏览 | Home · `/` · `/film/:id` | ~2100 行 | 3 |
| **B** | 订票 | Book tickets · `/booking` | ~1400 行 | 1（用例多） |
| **C** | 账户 · 取消 · 导航 | Login/Register/My bookings/Cancellation · 全局侧栏 | ~2100 行 | 2 |
| **D** | 数据管理 · 平台基础 | Data admin · 启动/种子/端口 | ~2100 行 | 4 |

**模块边界（只读，不修改对方代码）：**

| 交界 | 说明 |
|------|------|
| A → B | 详情页 Book 按钮带 `showingId` 跳转 `/booking` |
| B → C | B 写入 `Booking`；C 的取消服务读取并更新状态 |
| C → 全员 | `MainLayout` 控制各角色能看到哪些菜单 |
| D → 全员 | 种子数据为演示提供初始影片 / 场次 / 账号 |

## 与旧分工的主要变化

| 旧方案 | 新方案 | 原因 |
|--------|--------|------|
| C 只做 Cancellation | C 负责 **账户 + 取消 + 导航** | Cancellation 单独太轻（~600 行）；Auth 与 MainLayout 本是一体 |
| D 负责 Auth + Admin + Shell | D 只做 **Admin + 平台** | 原 D 负担过重且角色混杂 |
| A 只管 Home | A 额外含 **海报/媒体配置** | 与浏览模块强相关，避免无人负责 |
| 按层分「前端 / 业务」 | **按模块垂直切** | 每人对自己模块端到端负责 |
